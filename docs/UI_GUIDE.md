# TICKET HUB 画面づくりガイド

このガイドの目的は、**6人の誰が作っても同じ見た目になること**です。
そのために「自分で見た目を考える」部分をできるだけなくし、**決まったテンプレートと部品を組み合わせるだけ**で画面ができるようにしています。

## 0. 作り始める前に（必ずこの順番で）

1. `npm run dev` と `php artisan serve` を起動し、ブラウザで **http://127.0.0.1:8000/ui** を開く（見本ページ）
2. 下の「2. 画面パターン」から、自分の画面に当てはまるパターンを選ぶ
3. そのパターンのファイル（`resources/views/ui/〇〇.blade.php`）を**コピー**して、自分の画面ファイルを作る
4. 見本データを消してコントローラーからデータを渡し、文言を書き換える
5. 最後に「9. 提出前チェックリスト」を確認する

**白紙から書き始めないでください。** 必ずテンプレートのコピーから始めます。

## 1. 共通ファイル（勝手に変更しない）

| 役割 | ファイル |
|---|---|
| 色・フォント | `resources/css/theme.css` |
| 基本スタイル・切り取り線 | `resources/css/ui.css` |
| 上の2つを読み込む入口 | `resources/css/app.css` |
| 点検・自動修正ツール | `scripts/check-ui.mjs`（`npm run check:ui` / `npm run fix:ui`） |
| 画面の枠（ヘッダー・幅・左右カラム） | `resources/views/components/layout.blade.php` |
| 部品 | `resources/views/components/*.blade.php` |
| 日付・金額の表記 | `app/Support/Format.php` |
| 画面パターン（コピー元） | `resources/views/ui/*.blade.php` |
| 見本ページ | `/ui`（`resources/views/ui/index.blade.php`） |

これらを変えたいときは、**自分で直さずにチームに相談**してください。直すときは全員に共有します。

## 2. 画面パターン（どれを使うか）

| パターン | コピー元 | 幅 | 使う画面 |
|---|---|---|---|
| 絞り込み付き一覧 | `myticket.blade.php` | wide（サイドバーあり） | マイチケット |
| 縦の一覧 | `ui/list.blade.php` | medium | イベント一覧、マイメール、マイファンクラブ |
| 詳細 | `ui/detail.blade.php` | wide（サイドバーあり） | イベント詳細、マイQR、座席表 |
| 入力フォーム | `ui/form.blade.php` | narrow | 申し込みフォーム、アカウント登録、パスワード変更、ログイン、ファンクラブ加入、アカウント削除・ファンクラブ退会の確認 |
| 完了・結果 | `ui/complete.blade.php` | narrow | 申し込み完了、各種の完了画面 |
| メニュー | `ui/menu.blade.php` | narrow | マイページ |
| 表 | `ui/table.blade.php` | wide | 企業イベント一覧 |

- 当てはまらない画面（トップページなど）は、**作る前にチームで相談**してパターンを決めます。
- 幅は `<x-layout width="medium">` のように指定します。サイドバーがある画面は自動で wide になります。

## 3. 画面の枠（x-layout）

```blade
<x-layout title="マイQR" :back="['url' => route('myticket.index'), 'label' => 'マイチケットへ戻る']">
    <x-slot:sidebar> 左側（任意） </x-slot:sidebar>
    メインの内容
</x-layout>
```

| 指定 | 内容 |
|---|---|
| `title` | ブラウザのタブ名と、画面上の画面名（自分で `<h1>` を書かない） |
| `width` | `wide`（標準）/ `medium` / `narrow`（2. の表に従う） |
| `back` | 「← 〇〇へ戻る」リンク。前の画面が決まっているときに付ける |
| `sidebar` | 左カラム。中身は `<x-panel>` だけを並べる |

`return redirect(...)->with('error', '...')` や `->with('success', '...')` で渡したメッセージは、枠が自動で表示します。

## 4. 部品一覧

**部品にない見た目が必要になったら、画面の中で作り込まずにチームに相談**して部品を追加します。

| 部品 | 書き方 | 使う場面 |
|---|---|---|
| ボタン | `<x-button href="...">QRを表示</x-button>` | 5. のルールで種類を選ぶ |
| ボタンの並び | `<x-actions> 補助 → 主操作 </x-actions>` | フォームの下、完了画面 |
| 見出し付きのまとまり | `<x-section title="..." description="...">` | 1画面に区切りが2つ以上あるとき |
| 左の白い箱 | `<x-panel title="表示条件">` | サイドバーの中だけ |
| カード | `<x-card>` / `<x-slot:title>` / `<x-slot:footer>` | 白い箱で囲む内容、グリッドの1件 |
| チケット型カード | `<x-card ticket>` | **チケットそのもの**を表すときだけ |
| 縦の一覧 | `<x-list>` + `<x-list-item href="...">` | 1行ずつ並ぶもの。`<x-slot:aside>` で右側にラベル |
| 表 | `<x-table>` + 普通の `thead/tbody/tr/th/td` | 項目が4つ以上あり、横に比べたいデータ |
| 項目名と値 | `<x-info :items="['公演日' => ..., '会場' => ...]" />` | イベント情報、申し込み内容の確認 |
| 状態ラベル | `<x-badge status="当選" />` / `<x-badge color="primary">未読</x-badge>` | 6. の対応表に従う |
| メッセージ | `<x-alert type="success|error|info">` | 結果やエラーの説明 |
| 0件のとき | `<x-empty>…<x-slot:hint>…</x-slot:hint></x-empty>` | 一覧が空のとき（必ず hint を書く） |
| ページ送り | `<x-pagination :paginator="$events" />` | `->paginate(10)` した一覧の下 |
| フォーム | `<x-form :action="...">` + `<x-slot:actions>` | 入力画面（`@csrf` は自動） |
| 入力欄 | `<x-input name="..." label="..." required help="..." />` | 1行の入力。検索欄は `icon="search"` |
| 複数行の入力 | `<x-textarea name="..." label="..." rows="3" />` | 備考など |
| 1つ選ぶ | `<x-radio-group name="..." label="..." :options="[...]" required />` | 選択肢が**5個以下** |
| 1つ選ぶ（多い） | `<x-select name="..." label="..." :options="[...]" />` | 選択肢が**6個以上**、または並び替え |
| 複数選ぶ | `<x-checkbox name="xx[]" value="..." :checked="...">` | 絞り込み条件など |

## 5. 決まり（数値・選び方）

### ボタンの種類
| 種類 | いつ使うか | 1画面に |
|---|---|---|
| `primary`（青） | その画面でいちばん大事な操作（申し込む・保存・QRを表示） | **1か所だけ**（一覧なら1件につき1つ） |
| `success`（緑） | primary と並べる、もう1つの前向きな操作（座席表） | primary の隣だけ |
| `outline`（白） | 補助の操作（検索・キャンセル・戻る・編集） | 何個でも |
| `danger`（赤） | 取り消せない操作（退会・削除） | 確認画面の主操作だけ |

- 並べるときは「補助 → 主操作」の順に書く（`x-actions` が PC では右端、スマホでは一番上に主操作を置く）
- カードの中は `size="sm"`、それ以外は標準サイズ。フォームの送信ボタンは標準サイズ

### 文字
| 用途 | クラス | 備考 |
|---|---|---|
| 画面名 | （x-layout が自動） | 自分で書かない |
| 区切りの見出し | （x-section が自動） | 自分で書かない |
| カード・行の名前 | `font-bold`（カードは x-card の title） | |
| 本文 | （標準の `text-sm`） | |
| 補足 | `text-muted` | 日時・会場など2行目の情報 |
| 注記 | `text-xs text-muted` | 入力欄の補足は `help` を使う |

上の表にない文字サイズ（`text-3xl` など）は使いません。
例外：チケット型カードの公演日だけは大きく表示します（`myticket.blade.php` と同じ書き方をコピーする）。

### 余白・並べ方
- 画面の中のかたまり同士の間隔は x-layout が自動で付ける（`mt-8` などで調整しない）
- カードを横に並べるとき：`grid gap-4 sm:grid-cols-2 xl:grid-cols-3`（サイドバーあり）
- 行内の「1行目と2行目」の間：`mt-0.5`
- ボタン同士の間：x-actions / x-card の footer が自動で付ける

### 角の丸み・区切り
- 箱は部品に任せる（自分で `rounded-*` `ring-*` `shadow-*` を書かない）
- 影（`shadow-*`）とグラデーション（`bg-gradient-*`）は使わない

## 6. 表記のルール

### 日付・金額は Format を使う
```blade
{{ Format::date($day) }}        → 2026/11/24(火)
{{ Format::dateTime($day) }}    → 2026/11/24(火) 13:00
{{ Format::time($day) }}        → 13:00
{{ Format::price(9800) }}       → ¥9,800
{{ Format::count(2, '枚') }}    → 2枚
```
自分で `date('Y-m-d')` などで整形しないでください。数字だけの列やセルには `tabular-nums` を付けます。

### 状態ラベルの色
| 表示 | 書き方 |
|---|---|
| 当選（緑）・抽選中（黄）・落選（灰）・使用済（青） | `<x-badge :status="$status" />`（自動） |
| 受付中 | `<x-badge color="success">受付中</x-badge>` |
| 受付終了・期限切れ | `<x-badge color="muted">受付終了</x-badge>` |
| 未読・新着 | `<x-badge color="primary">未読</x-badge>` |
| エラー・停止中 | `<x-badge color="danger">停止中</x-badge>` |

### 文言
- ボタンは「何が起きるか」を書く：`申し込む` `QRを表示` `変更を保存` `退会する`（`送信` `OK` `はい` は使わない）
- 完了メッセージはボタンと同じ言葉で：`申し込む` → 「申し込みを受け付けました。」
- エラーは「何が起きたか ＋ どうすればよいか」：「このチケットは表示できません。マイチケットから選び直してください。」
- 0件表示は hint に次の行動を書く：「表示条件や検索キーワードを変えてみてください」
- 戻るリンクは行き先を書く：「マイチケットへ戻る」（「戻る」だけにしない）
- 「必須」は `required` を付ければ自動で出る（`*` や「※必須」を自分で書かない）

## 7. 色

色は **Tailwind に最初から入っている色**から選び、チームの名前を付けています（`resources/css/theme.css`）。
画面では右の Tailwind の色名ではなく、**左のチームの名前**で書きます。

| チームの名前 | 中身（Tailwind の色） | 書き方の例 | 用途 |
|---|---|---|---|
| `primary` / `-dark` / `-light` | `blue-600` / `blue-700` / `blue-50` | `bg-primary` | メイン操作・リンク |
| `success` / `-dark` / `-light` | `emerald-600` / `emerald-700` / `emerald-50` | `bg-success` | もう1つの前向き操作・当選・受付中 |
| `warning` / `-light` | `amber-700` / `amber-50` | `text-warning` | 抽選中・注意 |
| `danger` / `-light` | `red-600` / `red-50` | `text-danger` | エラー・削除 |
| `ink` | `slate-800` | `text-ink` | 本文 |
| `muted` | `slate-500` | `text-muted` | 補足 |
| `line` | `slate-200` | `ring-line` | 枠線 |
| `page` / `panel` / `surface` | `slate-100` / `slate-200` / `white` | `bg-surface` | ページ背景 / 控えめな面 / 白い面 |

**なぜ `bg-blue-600` と直接書かないのか**
- 人によって `blue-500` や `sky-600` を選んでしまい、色がそろわなくなるため
- 後でメインの色を青から別の色に変えたくなったとき、`theme.css` の1行を直すだけで全画面に反映できるため

Tailwind の色名で書いてしまった場合は、`npm run fix:ui` でいちばん近いチームの名前に書き換えられます。色見本は `/ui` で確認できます。

## 8. やってはいけないこと

| NG | 理由・代わりに |
|---|---|
| 色コード（`#2c5bc9`）や `style="..."` を書く | 色がずれる → 7. の色の名前を使う |
| Tailwind の色名を直接書く（`bg-blue-500` など） | 人によって色がずれる → チームの名前を使う（`npm run fix:ui` で直せる） |
| `[13px]` のような `[ ]` 付きのクラス | 数値がばらばらになる → 決まったクラスを使う |
| `<style>` や新しい CSS ファイルを作る | → 部品の追加をチームに相談（どうしても必要なら `app.css` の一番下に書く） |
| 部品で作れるものを `<button class="...">` などで手作りする | 見た目がずれる → 部品を使う |
| 自分で `<h1>` や画面名を書く | x-layout が出す |
| `$events->links()` を使う | 色がそろわない → `<x-pagination>` |
| チケット型カードをチケット以外に使う | 意味が伝わらなくなる |
| 共通ファイル（1. の表）を相談なしに変える | 他の人の画面も変わる |

- [ ] primary ボタンは1か所だけ（一覧は1件につき1つ）
- [ ] 日付・金額は `Format::` で表示している

## 10. 起動方法

```
npm install      （初回のみ）
npm run dev      （開発中は起動したままにする）
php artisan serve
```

- `npm run dev` を起動していないと「Vite manifest not found」エラーになります。
- `resources/css/` や `vite.config.js` を pull したあとは `npm run dev` を一度止めて再起動してください。
- 本番に配置する前は `npm run build` を実行し、`public/build` も一緒にアップロードしてください。
- `/ui` は開発中（`.env` の `APP_ENV=local`）だけ表示され、本番では表示されません。

## 11. 後から変更するとき（共通ファイルを直す人向け）

このガイドどおりに作られた画面は、見た目を部品と `resources/css/` だけに任せています。
そのため、下の「安全な変更」なら**全員の画面に自動で反映され、他の人は何もしなくてよい**です。

| 変更 | 安全？ | やり方 |
|---|---|---|
| 色を変える | ◎ | `theme.css` の右側（Tailwind の色）を選び直す（左の名前は変えない） |
| ボタン・カードなどの形や余白を変える | ◎ | `components/` の中のクラスを変える |
| フォントを変える | ◎ | `theme.css` の `--font-sans` と layout のフォント読み込みを変える |
| 部品に新しい指定を追加する | ◎ | `@props` に**初期値つき**で追加する（例：`'icon' => null`） |
| 新しい部品を追加する | ◎ | `components/` に追加し、`/ui` とこのガイドにも載せる |
| 色の名前を変える・消す（`primary` → `main` など） | ✕ | しない。どうしても必要なら古い名前も残す |
| 部品の名前や指定を変える・消す（`variant="success"` など） | ✕ | しない。どうしても必要なら古い指定も動くようにしておく |
| 部品の使い方（スロット名など）を変える | ✕ | しない。新しい部品として追加する |

共通ファイルを変えたら、必ず次の4つを行います。
1. `/ui` と各パターン（`/ui/list` など）を開いて崩れていないか見る
2. `npm run check:ui` を実行する
3. このガイドの版を上げ、「更新履歴」に何を変えたか書く
4. チームに「〇〇を変えました（画面側の作業は不要です／必要です）」と伝える

## 12. 後から合流した画面をそろえる（移行手順）

このガイドより前に作られた画面や、別のプロジェクトで作った画面をそろえる手順です。
**フォントと見出しは、共通 CSS を取り込んだ時点で自動でそろいます。** 色は自動書き換え、残りは点検ツールが場所を教えてくれます。

| そろい方 | 対象 |
|---|---|
| 自動（何もしなくてよい） | フォント、クラスなしの `<h1>〜<h3>` の大きさ |
| `npm run fix:ui` で自動書き換え | Tailwind の色名 → いちばん近いチームの名前（`bg-blue-500` → `bg-primary`、`text-gray-500` → `text-muted` など） |
| 手で直す（場所は `npm run check:ui` が表示） | 画面の枠、ボタン・入力欄などの手作り、`style=`、`[ ]` 付きクラス、影、文字サイズ |

### 手順
1. 共通ファイル（`resources/css/`、`components/`、`ui/`、`scripts/`、`docs/`、`package.json`）を取り込む（GitHub で pull）
2. `npm run dev` を再起動し、画面を開く（この時点でフォントと見出しはそろう）
3. 作業前の状態を Git でコミットしておく（自動書き換えを元に戻せるように）
4. `npm run fix:ui` を実行し、Tailwind の色名をチームの名前に書き換える → 画面を開いて色を確認
5. `npm run check:ui` を実行し、表示された場所を上から順に直す
   - `<!DOCTYPE>` `<html>` `<head>` `<body>` を消し、中身を `<x-layout title="画面名">` で囲む
   - `<h1>` を消し、画面名は `title` に入れる
   - `<button>` → `<x-button>`、`<input>` → `<x-input>` など、表示されたとおりに部品へ置き換える
   - 当てはまる画面パターン（2.）のテンプレートと見比べ、並べ方を合わせる
6. `npm run check:ui` で「違反はありません」と出たら、`/ui` と見比べて完了

他の人の画面を直すときは、**直す前に本人に伝え**、直した後に「何を変えたか」を共有してください。
